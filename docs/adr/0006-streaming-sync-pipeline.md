# Streaming Per-Course Sync Pipeline

We replace the batch discovery-then-download barrier (`CourseRepository.get_course_content`, `IDATSync.get_course_remote_tree`, `SyncDiff.from_trees`, `TaskOrchestrator.create_coroutines`, and batch `CourseFilesDiscovered`) with a streaming per-course pipeline so inline HTML (`StringContent`) and zero-I/O Moodle files (`MoodleContent`) start downloading and rendering in `CourseTree` immediately while rate-limited SharePoint link and recording lookups run concurrently. Superseding the batch-diff notes in ADR-0001 and ADR-0004, `domain/sync.py` drops `SyncDiff`/`SyncEntry`/`SyncStatus` in favor of a pure per-item `is_content_pending(content, local_mtimes)` check (extended by `DownloadManager.is_pending` for `StringContent` byte comparison), and `TaskOrchestrator` exposes a per-run `TaskChannel` with one unbounded `asyncio.Queue` per rate-limit group.

To keep path disambiguation deterministic under concurrent resolution without relying on nonexistent Moodle content IDs, `CourseRepository.stream_course_content` resolves one task per `CourseModule` (resolving `module.contents` sequentially in Moodle order under each module's unique `...-[<module.id>]` directory) while `IDATSync.sync_course` runs `stream_course_content` and `get_recordings` concurrently, isolates `get_recordings` `RemoteServiceError` without aborting active downloads, applies a pure `PathDisambiguator` (`domain/path_utils.py`), and emits per-file `CourseFileDiscovered` events (strictly before enqueueing each download task) followed by `CourseDiscoveryCompleted` so `CourseTree` transitions cleanly from indeterminate `"Fetching & Syncing"` (`"done/total+"`) to exact percentage `"Syncing"`. `SharepointClient.get_client_from_url` creates a fresh `ClientContext` on fallback so concurrent SharePoint URL tasks never share mutable context state, while `UrlContentStrategy.list_url_content` and course-to-course iteration in `sync_courses` remain non-streaming.
