# Spec Delta

## ADDED Requirements

### Requirement: User-friendly UI error summaries with raw error logging
`src/idat_sync/application/exceptions.py` (re-exported from `src/idat_sync/application/ports.py`, with zero third-party SDK imports) SHALL expose typed, optional keyword-only structured metadata attributes on `IDATSyncError` subclasses while keeping `str(exc)` as the full diagnostic message:
- `ServiceName = Literal["Moodle", "SharePoint"]`, `AuthFailureReason = Literal["credentials", "mfa", "timeout", "sharepoint"]`, and `FileSystemOperation = Literal["access", "write"]`.
- `AuthenticationError(message: str, *, reason: AuthFailureReason = "credentials")` storing `self.reason`.
- `CredentialsExpiredError(message: str, *, service: ServiceName | None = None)` storing `self.service`.
- `FileSystemError(message: str, *, operation: FileSystemOperation = "access")` storing `self.operation`.
- `RemoteServiceError(message: str, *, service: ServiceName | None = None, status_code: int | None = None, is_network: bool = False)` storing `self.service`, `self.status_code`, and `self.is_network`.
- `CredentialStoreError` and base `IDATSyncError` remain unchanged.

Infrastructure `raise` sites SHALL populate those domain/port facts without embedding English UI phrasing:
- `SharepointBrowserAuth` passes `reason="mfa"` on empty MFA code, `reason="timeout"` on `TimeoutError`, and `reason="sharepoint"` on generic browser authentication failures.
- `MoodleTokenClient` and `MoodleClient` pass `service="Moodle"` on all `CredentialsExpiredError` and `RemoteServiceError` raises, plus `status_code` on HTTP status errors and `is_network=True` on `httpx.RequestError`.
- `SharepointClient` passes `service="SharePoint"` on all `CredentialsExpiredError` and `RemoteServiceError` raises, plus `status_code` on `ClientRequestException` (when an integer HTTP status is present) / `httpx.HTTPStatusError`, and `is_network=True` on non-HTTP `httpx.HTTPError`.
- `downloaders.py` passes `operation="write"` on `_atomic_download` and recording write `OSError` (leaving directory creation and `LocalFileSystemAdapter` on default `operation="access"`), and `RecordingDownloader` passes `service="SharePoint"` on `CredentialsExpiredError` and `RemoteServiceError` plus `status_code=cause.code` on `urllib.error.HTTPError` and `is_network=True` on `urllib.error.URLError | TimeoutError`.

`src/idat_sync/ui/error_format.py` SHALL expose a pure-Python function `format_ui_error(exc: IDATSyncError) -> str` (importing only from standard library and `idat_sync.application.exceptions` / `idat_sync.application.ports`, with zero `idat_sync.infrastructure` imports) that maps every `IDATSyncError` subclass strictly from its exception class and structured attributes (NEVER inspecting `str(exc)` with regex or substring matching) to a concise English summary using `GLOSSARY.md` vocabulary (`Credentials`, never `Session`):
- `AuthenticationError`: `"Verification code is required"` for `reason == "mfa"`, `"Sign-in timed out — try again"` for `reason == "timeout"`, `"SharePoint sign-in failed — try again"` for `reason == "sharepoint"`, otherwise `"Sign-in failed — check your username and password"`.
- `CredentialsExpiredError`: `f"{exc.service} credentials expired — sign in again"` when `exc.service` is set, otherwise `"Credentials expired — sign in again"`.
- `CredentialStoreError`: `"Could not update stored credentials"`.
- `FileSystemError`: `"Could not save file to disk"` when `exc.operation == "write"`, otherwise `"Could not access local folder"`.
- `RemoteServiceError`: `f"{exc.service or 'Server'} error (HTTP {exc.status_code})"` when `exc.status_code is not None`; else `f"{exc.service or 'Network'} connection error"` when `exc.is_network` is `True`; else `f"{exc.service} error"` when `exc.service` is set; otherwise `"Remote service error"`.
- Base `IDATSyncError` fallback: `"Unexpected sync error"`.

All raw technical error strings SHALL continue to be logged in full to the configured log file without altering `domain/`, `application/events.py`, `application/sync_service.py`, `frontend/`, `src/idat_sync/ui/index.html`, or `log_sync_event`. Verified at the `idat_sync.application.exceptions`, `MoodleTokenClient`, `MoodleClient`, `SharepointClient`, `SharepointBrowserAuth`, `downloaders`, `idat_sync.ui.error_format`, `SyncFrame`, and `LoginFrame` seams.

#### Scenario: Summarizing RemoteServiceError from structured attributes without parsing raw text
- **WHEN** `format_ui_error` is called with `RemoteServiceError("SharePoint error: ('400', ...)", service="SharePoint", status_code=400)`, `RemoteServiceError("HTTP 500 ...", service="Moodle", status_code=500)`, `RemoteServiceError("HTTP 404 ...", status_code=404)`, `RemoteServiceError("SharePoint request failed", service="SharePoint", is_network=True)`, `RemoteServiceError("Network error", is_network=True)`, `RemoteServiceError("SharePoint error on file 500_lab.pdf", service="SharePoint")`, and `RemoteServiceError("ERROR: yt-dlp failure")`
- **THEN** it returns `"SharePoint error (HTTP 400)"`, `"Moodle error (HTTP 500)"`, `"Server error (HTTP 404)"`, `"SharePoint connection error"`, `"Network connection error"`, `"SharePoint error"` (ignoring `"500"` in the filename), and `"Remote service error"` respectively, containing no URLs or tuple syntax

#### Scenario: Summarizing AuthenticationError, CredentialsExpiredError, CredentialStoreError, FileSystemError, and base IDATSyncError from structured attributes
- **WHEN** `format_ui_error` is called with `AuthenticationError("MFA code is required", reason="mfa")`, `AuthenticationError("SharePoint sign-in timed out.", reason="timeout")`, `AuthenticationError("SharePoint browser authentication failed", reason="sharepoint")`, `AuthenticationError("Authentication failed: empty token or SharePoint storage state.")`, `CredentialsExpiredError("HTTP 403", service="SharePoint")`, `CredentialsExpiredError("HTTP 401", service="Moodle")`, `CredentialsExpiredError("401 Unauthorized")`, `CredentialStoreError("Could not create credentials file: [Errno 13]")`, `FileSystemError("Failed to write 'C:\\secret\\a.pdf'", operation="write")`, `FileSystemError("Could not scan 'C:\\courses\\write_notes'")`, and `IDATSyncError("internal detail")`
- **THEN** it returns `"Verification code is required"`, `"Sign-in timed out — try again"`, `"SharePoint sign-in failed — try again"`, `"Sign-in failed — check your username and password"`, `"SharePoint credentials expired — sign in again"`, `"Moodle credentials expired — sign in again"`, `"Credentials expired — sign in again"`, `"Could not update stored credentials"`, `"Could not save file to disk"`, `"Could not access local folder"` (ignoring `"write"` in the folder path), and `"Unexpected sync error"` respectively

#### Scenario: Populating structured metadata at infrastructure raise sites
- **WHEN** `MoodleTokenClient`, `MoodleClient`, `SharepointClient`, `SharepointBrowserAuth`, and `downloaders` translate transport, HTTP, auth, or disk failures into `IDATSyncError` subclasses
- **THEN** every raised exception preserves its diagnostic `str(exc)` message AND carries accurate `.reason`, `.service`, `.operation`, `.status_code`, and `.is_network` attributes

## MODIFIED Requirements

### Requirement: Treeview course selection UI and ProgressInterceptor removal
`src/idat_sync/ui/app.py` MUST NOT define `ProgressInterceptor` and MUST NOT reassign `sys.stdout` or `sys.stderr`, and `idat_sync.main.main()` SHALL invoke `configure_logging(config.log_file)`. `MainApp` SHALL create desktop windows with default size `width=1100, height=720`, expose `push_progress(self, payload: dict[str, Any]) -> None` (calling `window.evaluate_js(f"window.__onFileProgress({json.dumps(payload)})")` when `window` is attached) alongside `push_state()`, and expose `_JsApi` methods `get_state`, `login`, `submit_mfa`, `cancel_mfa`, `browse_folder`, `select_in_progress`, `select_all`, `clear_selection`, `toggle_course`, `toggle_term`, `sync`, `sync_course`, `cancel_sync`, `retry_load`, and `logout`. `SyncFrame` in `src/idat_sync/ui/sync_frame.py` MUST NOT define `output_text`, `_TreeProgressListener`, `progress_queue`, `update_progress`, `exit`, or `_queue_error`, and MUST NOT call `loop.call_soon_threadsafe` or `asyncio.to_thread`. `SyncFrame` SHALL expose:
- `toggle_course(course_id: int)`, `toggle_term(term: str)` (tri-state: selects all courses in `term` if any are unselected, otherwise deselects all courses in `term`), `select_in_progress()`, `select_all()`, and `clear_selection()`,
- `do_sync()` synchronizing `selected_course_ids` (or falling back to `in_progress_ids` when `selected_course_ids` is empty, or all loaded courses when `in_progress_ids` is also empty) and `sync_course(course_id: int)` synchronizing a single course on demand (enabled whenever `not is_syncing` and `folder_path` is non-empty, even after prior sync completion), both single-job guarded via `_busy`,
- `cancel_sync()` cancelling the active sync task cleanly via `asyncio.CancelledError` without closing `self.idat_sync`, reverting in-flight `Downloading` and queued `New`/`Outdated` rows back to their discovered `New`/`Outdated` state while preserving `Completed` and `Synced` rows, resetting `is_syncing` to `False`, and setting `self.status = "Sync cancelled."`,
- `retry_load()` re-running `load_idat_sync(self.credentials)` when startup loading failed (`not courses_loaded and not is_syncing`),
- `to_dict()` returning `view`, `folder_path`, `status`, `error`, `auth_expired`, `courses_loaded`, `is_syncing`, `can_sync`, `courses`, and `activity`.
On `TaskDownloadFailed(path, error)`, `SyncFrame` SHALL record `format_ui_error(error)` (without a per-row log-file hint) on the failed file row in `CourseTree`. When `sync_courses` completes with at least one `CourseSyncCompleted(..., error != None)`, `SyncFrame` SHALL set `self.status = "Sync completed with errors."` and set `self.error` to `f"{failed_count} {'file' if failed_count == 1 else 'files'} failed to download. Check {self.config.log_file.name} for details."` when `failed_count > 0` in `self.course_tree.activity_to_dict()`, or `f"{format_ui_error(first_error)}. Check {self.config.log_file.name} for details."` when `failed_count == 0`. `CourseTree` in `src/idat_sync/ui/course_tree.py` SHALL assign each course its parsed `term` (`get_course_term(course)`) and `in_progress` flag (ordering courses newest-term-first with in-progress courses first), assign each file node a stable unique `id` (`f"file:{course_id}:{rel.as_posix()}"`), represent file statuses via `RowStatus` (`IDLE`, `QUEUED`, `FETCHING`, `FETCHING_AND_SYNCING`, `SYNCING`, `SYNCED`, `NEW`, `OUTDATED`, `DOWNLOADING`, `COMPLETED`, `FAILED`), record `error: str` on failed files, compute smoothed `speed_bps` and `percent` (clamped to `0..99` while `DOWNLOADING` when `total > 0`, `None` when `total is None`, and `100` when `SYNCED` or `COMPLETED`) in pure Python via `set_file_progress(path, downloaded, total) -> dict[str, Any] | None`, revert in-flight/queued rows on `cancel_sync()`, and expose `activity_to_dict()` (reporting `total_pending`, `completed`, `skipped`, `failed_count`, `percent`, `downloading`, `queued`, `finished`, and `failed` lists). On `TaskDownloadProgress`, `SyncFrame` SHALL update `CourseTree.set_file_progress(...)` and call `self.app.push_progress(payload)` WITHOUT triggering a full `push_state()`. `frontend/` SHALL compile a Vite + SolidJS (`createStore` + `reconcile`) + Tailwind CSS + `vite-plugin-singlefile` bundle into `src/idat_sync/ui/index.html` per ADR-0008 implementing the responsive 3-pane desktop (`>= 960px`) and mobile bottom-sheet `CourseSync` UI with native pywebview window chrome, offline system fonts, light/dark theme toggle, streamlined Login + 6-digit MFA, empty-folder onboarding (ephemeral `folder_path`), parsed-term sidebar grouping (newest expanded, older collapsed) with tri-state term & course checkboxes and selection bar, recursive collapsible folders with automatic single-child `Parent › Child` collapsing, file extension badges, filter chips (including conditional `Failed`), Cancel button while syncing (with no Pause/Resume control), and errors surfaced in the Status strip (`.syncbar` / onboarding card with `Sign out` on `CredentialsExpiredError` and `Retry` on startup error) and ActivityPanel (`Failed` section + red pills). Verified at the `MainApp` (`src/idat_sync/ui/app.py`), `idat_sync.main.main` (`src/idat_sync/main.py`), `CourseTree` (`src/idat_sync/ui/course_tree.py`), `SyncFrame` (`src/idat_sync/ui/sync_frame.py`), and `src/idat_sync/ui/index.html` seams.

#### Scenario: Ordering in-progress courses first and pre-selecting them on startup
- **WHEN** `await SyncFrame.load_idat_sync(credentials)` loads courses from `await idat_sync.list_courses()` across multiple terms (including split categories `"I.01.2025-IIA"` and `"I.03.2025-IIA"` plus `"IV.01.2026-III"`) and invokes `toggle_term("2025-IIA")` twice, `select_in_progress()`, and `clear_selection()`
- **THEN** `SyncFrame` delegates to `CourseTree` to order courses newest-term-first with `in_progress == True` and `checked == True` on the highest term (`"2026-III"`) and `term == "2025-IIA"` on both split courses, the first `toggle_term("2025-IIA")` selects all `"2025-IIA"` courses and the second deselects them, `can_sync` is `True` when `not is_syncing` and `folder_path` is non-empty, and `sync_course(course_id)` stays runnable whenever idle with `folder_path` set even after a prior sync completed

#### Scenario: Updating parent course and child file rows during sync
- **WHEN** `await SyncFrame.do_sync()` runs on target courses receiving `CourseSyncStarted`, `CourseFileDiscovered(..., ContentSyncState.SYNCED / NEW / OUTDATED)`, early `TaskDownloadStarted`/`TaskDownloadProgress(path, 500, 1000)`/`TaskDownloadProgress(path, 1000, 1000)`/`TaskDownloadCompleted` before `CourseDiscoveryCompleted`, indeterminate `TaskDownloadProgress(path2, 256, None)`, `CourseDiscoveryCompleted`, and `CourseSyncCompleted`
- **THEN** `hasattr(SyncFrame, "update_progress")` and `hasattr(SyncFrame, "exit")` are `False`, only target courses reset to `(RowStatus.QUEUED, "0%")` and are passed to `sync_courses(..., refresh=True)`, `add_file` inserts nested folders and leaf file nodes with stable `id` (`New`/`Outdated`/`Synced`), each `TaskDownloadProgress` invokes `app.push_progress(payload)` without calling `app.push_state()` while clamping in-flight `percent` to `0..99` (`50`, `99` at `1000/1000`, `None` for indeterminate) and updating pure-Python `speed_bps` and `activity_to_dict()`, `finish_discovery` transitions the course to `(RowStatus.SYNCING, f"{int(done * 100 / total)}%")` (`"100%"` on an empty course), and `CourseSyncCompleted` marks `(RowStatus.COMPLETED, "100%")` or `(RowStatus.FAILED, current_progress)`

#### Scenario: Reporting completion error status in SyncFrame
- **WHEN** `await SyncFrame.do_sync()` finishes iterating `sync_courses` after `TaskDownloadFailed(path, FileSystemError("Failed to write 'C:\\a.pdf': disk full", operation="write"))` and `CourseSyncCompleted(course, error)` vs after a course-level `CourseSyncCompleted(course, RemoteServiceError("boom"))` with zero failed files vs when all had `error is None`, or when `load_idat_sync` fails on startup
- **THEN** `self.status` is `"Sync completed with errors."` when any course had an error and `"Sync done."` when all succeeded, failed file rows store `"Could not save file to disk"` (without raw paths or log-file hint) in `error` and appear in `activity["failed"]`, `self.error` is `f"1 file failed to download. Check {self.config.log_file.name} for details."` when 1 file failed (or `f"{n} files failed to download. Check {self.config.log_file.name} for details."` for multiple) and `f"Remote service error. Check {self.config.log_file.name} for details."` when zero files failed, and startup errors set the summarized `error` with log hint and `courses_loaded == False` so `retry_load()` retries initialization

#### Scenario: Clearing selected course sections on repeat Sync without recreating IDATSync
- **WHEN** `await SyncFrame.do_sync()` runs a second time on target courses with already-populated `sections` while untargeted courses retain cached `sections`
- **THEN** `IDATSync.sync_courses(path, target_courses, refresh=True)` clears `Course.sections` for targeted courses, untargeted `Course.sections` remain untouched, and `create_sync_service` is not invoked again while `self.idat_sync` is already active

#### Scenario: Cancelling an active sync without closing IDATSync or losing completed files
- **WHEN** `SyncFrame.cancel_sync()` is triggered while `do_sync()` or `sync_course(course_id)` is downloading one file with another file still `New`/`Outdated` and one file already `Completed`
- **THEN** the active sync task is cancelled via `asyncio.CancelledError`, `self.idat_sync` remains non-`None` and unclosed for subsequent syncs, `is_syncing` resets to `False`, `status` becomes `"Sync cancelled."`, the completed file remains `RowStatus.COMPLETED` (`100%`), and the in-flight/queued files revert to their discovered `RowStatus.NEW` / `RowStatus.OUTDATED` state with `percent == 0`
